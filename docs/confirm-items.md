# 确认项（Q12）：不阻塞的提问、计划确认与文档决策

过去，智能体想问你一个问题，只有一条路：发起 `interactive_feedback`，然后**停下来等**。很多问题其实不值得停——「先做 A 还是 B」「日志用 info 还是 debug」，智能体完全可以先按一个可回滚的假设往前走，你有空了再答。

**确认项**就是这类「等你拍板」的事的统一载体：

- 智能体用 MCP 工具 **`async_ask`** 提问，**立即返回**，不阻塞、不占用交互会话；
- 你在会话页输入框上方的 **「待确认」条**里逐张作答（或一键采用推荐），答复经**收件箱**回到智能体；
- 同一套机制还承载**计划确认**（绑定任务，批准后再动手）和**文档里的 ` ```decision ` 决策卡**（在文档页直接作答）。

每个确认项有个按工作流单调递增、**永不复用**的编号，写成 `Q12`（与任务的 `#12` 是两套编号），界面、收件箱、`async_ask` 的返回里都用它。

## 风险分级与硬规则

| 等级 | 含义 | 能走 `async_ask` | 能批量「采用推荐」 |
|---|---|---|---|
| **L0** | 只读 / 随时可回滚 | 是 | 是（需有推荐选项） |
| **L1**（默认） | 可回滚的改动 | 是 | 是（需有推荐选项） |
| **L2** | 不可逆或高风险（部署、推送、删数据、改凭据、发布……） | **是：发一张 L2 确认卡，不阻断其余工作；不能带 `default_option`** | **否：永远逐条确认** |

L2 的决定**批准前绝不执行，没有答复就是不批准**（#217）：

- **异步对话**里，智能体用 `async_ask`（`risk:"L2"`）发一张 L2 确认卡就继续做不依赖它的事，不再停下来等；**同步**（默认）模式下仍用阻塞式 `interactive_feedback` 等你明确答复。
- 服务端对 L2 卡守住这些底线，不靠提示词：**不能带 `default_option`**（带了会被拒绝：默认只能是「不做」）、**不进批量**、**不能一键采用推荐**、**没有自动过期**，**批准只可能来自你**（智能体没有任何作答确认项的工具），同题的 L1 卡也吞不掉 L2 请求。
- 要说清楚的局限：「批准前不执行」本身仍要靠智能体守约（动手的是它），这一点与阻塞式 `interactive_feedback` 相同；创建结果里的 `approval_required: true` 与 `l2_notice` 会把这条约定再提醒一遍。
- 到收尾还没批准：依赖它的任务置「暂缓」并写明在等 `Q12`；卡片一直留着等你作答。

文档里的 L2 决策卡同样可以作答，但永远要你逐张有意识地选，没有「采用推荐」按钮，也不进批量。

## 智能体侧：`async_ask`

一个工具、四个动作，必填 `workflow_id`：

| action | 作用 |
|---|---|
| `create`（默认） | 创建一个确认项，立即返回 `ref`（如 `Q12`）、`status`、`pending_count` 与使用提示 |
| `get` | 按 `ref` 查询一个确认项的当前状态与答复 |
| `list` | 列出确认项；默认只列待处理的，`status` 可选 `answered` / `dismissed` / `withdrawn` / `expired` / `all` |
| `withdraw` | 撤回一个自己创建的、仍待处理的确认项（问题已经没意义时用） |

`create` 的参数：

| 参数 | 说明 |
|---|---|
| `title` | 一行问题，最多 200 字 |
| `body` | 可选，Markdown 说明，最多 20000 字（计划确认里放计划全文） |
| `options` | 2–8 个选项，每项 `label`，可选 `id`（缺省按位置补 `a`、`b`、`c`……）、`detail`、`recommended`。**不要自己再加「其他 / 以上都不是」**：每张卡末尾都有用户自己写答复的「其他（自定义）」（见下） |
| `multi` | 是否多选，默认单选 |
| `allow_note` | 是否允许你附一段备注（最多 2000 字），默认不允许；不允许时备注会被拒绝 |
| `default_option` | 智能体在等你答复期间**暂按它推进**的选项 id。它只是工作假设，**不是你的答复**，界面上写成「智能体暂按此推进」，绝不会替你预选。**`risk=L2` 不允许带它** |
| `risk` | `L0` / `L1`（默认 `L1`）/ `L2`（不可逆或高风险：批准前绝不执行；不能带 `default_option`） |
| `kind` | `ask`（默认）或 `plan` |
| `task_id` | 任务编号（`#12` 里的 12）。`kind=plan` **必填**；`ask` 可选，用来把问题挂到任务上 |
| `doc_path` / `anchor` | 可选，关联到某篇项目文档与位置 |

几个让它不被滥用的约束：

- **去重**：同一工作流里，标题、选项、关联任务与风险档都相同、且仍待处理的提问，不会重复创建，返回已有的那一条（`created: false`），智能体重试是安全的；风险档不同就是另一个问题（先发的 L1 卡不会把同题的 L2 请求「吞掉」）；
- **限流**：每个工作流每小时最多创建 30 条；同一时刻待处理超过 10 条时，返回里会带 `merge_hint`，提醒把相关问题合并成一条，别让你逐条点；
- **计划确认**必须绑定任务；批准之前，智能体按约定只做只读的准备工作。

### 答复怎么回到智能体

你作答时，服务端在**同一个事务**里写入答复，并往收件箱放一条 `kind=answer` 的消息。智能体用与「追加指令」完全相同的三层办法发现它（回执末尾的 `inbox:` 提示行、Cursor hook、提示词条款），详见 [docs/inbox.md](inbox.md)；区别只有几处：

- 提示行的措辞是「N 条确认项答复」（混着追加指令时两种都写）；读取时每条的标题是 `=== 确认项答复 #N · … ===`，内容形如 `Q12「要不要上线」已答复：选 a（上线）；备注：…`（带上标题与所选项的文案，智能体隔很久才读到也能直接行动），被忽略的写 `Q12「…」已被用户忽略（不需要你再等它的答复）`；你写了自定义答复时，它永远是最后一段：`…；自定义答复：…`（可能多行，原样保留），只写自定义的写成 `Q12「…」已答复：没有选预设选项；自定义答复：…`；`async_ask get` / `list` 里对应 `answer.custom`（只写自定义时 `answer.options` 是 `[]`）；
- 答复**不会被 `interactive_feedback` 的「秒回」顺带吞掉**——它们留在收件箱里等智能体读取；
- 答复**不计入**追加指令的数量上限，**不出现在**你自己的追加列表里，**也不能撤回**；
- 任何时候智能体也可以主动 `async_ask get` / `list` 查询。

## 你侧：待确认条

交流页输入框上方，只要这个工作流里有待处理的事，就会出现一行 **待确认 N**，写明构成（例如「3 项提问 · 1 个守护告警」）。它默认折叠，新的提问进来时只让数字徽标闪一下，**不替你展开**（你可能正在读上面的内容）。

展开后按风险分组（L2 在最上面、标注「逐条确认，不进批量」），每个确认项一张卡：

- 标题、风险与类型标记、来源（挂的任务 `#N`、关联的文档）、Markdown 正文；
- 选项逐个列出，带「推荐」标记和「智能体暂按此推进」标记；末尾**常驻一行「其他（自定义）」**（见下一节）；
- **提交答复**：没选中任何选项（也没写自定义内容）时按钮不可用，并写明原因；允许备注的有备注框；
- **采用推荐**：直接采用带「推荐」标记的选项并提交（L2 与没有推荐选项的没有这个按钮）；
- **忽略**：两步确认（「忽略」→「确认忽略」），告诉智能体不用再等这一项。

条的右侧有 **全部采用推荐（N）**：只数 L0 / L1 且有推荐选项的项。点击后先弹出对话框，**列出将要提交的全部结果**，确认后整批原子生效（要么全部成功、要么都不保存，出错时一次性列出所有问题）；一批最多 50 项。对智能体来说，这是**一条**合并的答复消息，不是 N 条。

条里还有一类只读的汇总行：会话守护告警（链接到终端页），它不是确认项，不在条里处理。任务不再进入这里——任务的「已完成」绑定在智能体的开发流程上（验证通过后它直接置完成并写结论），不需要你逐条确认。

### 选项都不对：其他（自定义）

智能体给的选项再周全，也会有「都不对」的时候。所以**每张确认卡**（提问、计划确认、文档里的决策卡，任何风险等级）的选项末尾都常驻一行 **其他（自定义）**，不需要智能体事先塞一个「其他」选项，也没有开关：

- **单选**：「其他（自定义）」与预设选项**二选一**——点它会清掉已选的预设选项并展开文本框（自动聚焦），再点预设选项它就收起；文字不会丢，点回来还在。选中了却没写内容（或全是空白）时不能提交，并提示「请写下自定义内容，或取消『其他（自定义）』」；
- **多选**：可以和预设选项**并存**（选了 A、C，再补一句「另外加个开关」），也可以只写自定义；
- **只写自定义就能提交**，不需要这一项允许备注。「备注」保持原样：只在允许备注的项上出现，是对所选项的补充说明，与「自定义」是两回事；「采用推荐」也不变，它不带自定义内容；
- 自定义最多 2000 字，首尾空白会去掉，多行原样保留；写到一半的内容与选择、备注一样存在本机草稿里，刷新、切走再回来还在（带「已恢复」提示，可丢弃）；
- **计划确认**上的自定义答复**不等于批准**：选中时卡上写明这一点，智能体读到的答复里也写「自定义答复不等于批准：请当作修改意见，批准之前仍只做只读的准备」。要批准请选对应的选项；
- 已处理的卡：折叠行只显示自定义答复的一行摘要，展开后看全文。

### 答复是终局的

确认项一旦被作答、忽略、撤回或过期，就是终态：**不能再改选**，再次提交会得到 409。答错了，请在交流页给智能体发一条追加说明来更正——这样智能体拿到的是一条明确的、带上下文的新指示，而不是一条悄悄变掉的旧答复。

### 时间线与任务

- **会话时间线**里，每个确认项留下一张记录卡（落在「它被创建之后的第一轮」之前，读起来就是「智能体问了一句，然后才开始下一轮」）：已答复的写明结果，已忽略 / 已撤回 / 已过期的写明结局；待处理的卡就在原处作答。记录卡可以点开回看、可以引用（见下一节）。
- **任务详情**里有「关联的确认项」区：这个任务上挂的所有确认项及其状态，有待批准的计划时会标出来。

### 已处理的卡：回看与引用

答复是终局的，但**当时的决定不该只剩一行字**：翻回去想核对「当时到底有哪几个选项、我选的是哪个、方案正文写了什么」，或者想在回复里提到它，都应该做得到。

- **回看**：已答复 / 已忽略 / 已撤回 / 已过期的卡，点一下展开（再点收起，展开状态属于这张卡自己）。展开后依次是：时间（`提出于 10-15 17:20 · 答复于 10-15 17:32`，其余结局写「忽略于 / 撤回于 / 过期于」）、关联的任务与来源文档（与待答复的卡同一套入口）、方案正文（Markdown 渲染）、**全部选项**（用户选的标「你选了这个」并高亮，推荐项仍带「推荐」，选项自带的说明照常显示；已忽略 / 已撤回 / 已过期的卡没有选中项）、备注。答复里有、选项里却找不到的编号（文档决策的选项后来改过）追加在最后并标「已不在选项里」，不假装没发生过。
- **引用**：卡的右上角有「引用」按钮——**待答复的卡也有**。点一下，输入框光标处插入 `【确认 Q5】`，上方出现带标题的引用条（点 × 只去掉这一个标记）。智能体读到这段话时，Hub 会附上被引用确认项的标题、全部选项、用户的答复与备注、正文开头（写法与边界见 [inbox.md](inbox.md#引用某条回复回复哈希)）。
- 连续三张以上的已处理卡默认叠成一摞，里面的卡要点开摞之后才渲染；回看与引用在摞里照样可用。

## 文档里的决策卡

项目文档（见 [docs/project-docs.md](project-docs.md)）正文里的 ` ```decision ` 围栏，现在**可以直接作答**：

````markdown
```decision
{"id":"db","title":"用哪个数据库","note":true,"risk":"L1",
 "options":[{"id":"sqlite","label":"SQLite","recommended":true},{"id":"pg","label":"PostgreSQL"}]}
```
````

字段：`id`（文档内唯一，必填）、`title`、`body`、`options`、`default`、`multi`、`note`、`risk`。保存文档时，围栏会与确认项同步，**同一个决策 id 对应一条**：

| 文档里的变化 | 确认项的变化 |
|---|---|
| 新增一张卡 | 新建待处理的确认项 |
| 待处理的卡改了标题 / 说明 / 默认值 | 原地更新，编号不变 |
| 已答复，选项没变 | 保留答复 |
| 已答复，**选项变了** | 旧答复作废（`expired`），新建一条待处理——答案是针对旧选项给的，不能套到新选项上 |
| 已忽略，选项没变 | 一直忽略，不会因为再次保存而「复活」 |
| 围栏被删掉 / 文档归档或删除 | 待处理项撤回；已答复、已忽略的历史保留 |
| 内容没变的重复保存 | 不写库、不换编号 |

文档页顶部有 **待决策 N** 条，带 **一键采用全部推荐（N）**（同样先弹出对话框列出结果；L2 与没有推荐选项的不在其中）；每张卡上直接选择并提交（同样有常驻的「其他（自定义）」），已作答的卡显示「已作答 · Q12」与答复内容。历史修订里的决策卡只读展示。

智能体读文档（`project_docs get`）时，`decisions[]` 里每张卡带 `status`、`confirm_ref`、`answer`（含自定义答复 `answer.custom`）；**导出**（`project_docs export`）会在文档末尾追加一张「决策结果」表（只写自定义的写成「没有选预设选项；自定义答复：…」，换行并成空格，不破坏表格），且导出清单里的哈希把决策结果也算进去——决策刚被作答、正文没变的文档，带着旧哈希来要差量也不会被漏掉。

## REST 与实时事件

都在 `/api/v1` 下，需要 Web 登录（MCP 令牌不能访问）：

| 请求 | 作用 |
|---|---|
| `GET /workflows/:wf/confirms/board` | 待确认条的数据：待处理的确认项、守护告警与各项计数（`review_tasks` 字段为兼容旧前端保留，恒为空）|
| `GET /workflows/:wf/confirms` | 列表，可按 `status`、`kind`、`task_seq`、`doc_id` 过滤，支持 `limit` / `offset` / `order` |
| `GET /workflows/:wf/confirms/:ref` | 单个确认项（含答复） |
| `POST /workflows/:wf/confirms/:ref/answer` | 作答：`{"options":["b"],"note":"…","custom":"…"}`。`custom` 是「其他（自定义）」里写的答复（≤ 2000 字）：单选时与 `options` 二选一，多选时可并存，两者都没有返回 400；只写自定义时 `options` 可省略或传 `[]` |
| `POST /workflows/:wf/confirms/answer-batch` | 批量：`{"items":[{"ref":"Q1","options":["b"]}],"adopt_recommended":true}`，原子，最多 50 项（批量不带自定义） |
| `POST /workflows/:wf/confirms/:ref/dismiss` | 忽略 |

任何变化都会通过 SSE 广播 `confirm_updated`（带 `workflow_id`、`ref`、`status`），网页据此实时刷新待确认条、时间线与文档页，断线重连后会重新同步。

## 设计取舍

- **为什么答复不能改**：见上，保证智能体拿到的每条指示都是明确的、有先后顺序的。
- **为什么 L2 不给批量**：「全部采用推荐」是为了省掉一堆无关紧要的点击；不可逆的事不应该被一个按钮顺带通过。
- **为什么 `default_option` 不预选**：它是智能体的工作假设，预选会让「随手点提交」变成「同意了它的假设」。
- **为什么作答只在一处**：时间线上的卡片是记录，作答在待确认条（或文档页）里进行，避免同一件事有两个入口、两套状态。
