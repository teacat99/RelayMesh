# 手机 / 桌面推送（ntfy）

网页上的提示音与系统通知，只有「网页开着、并且连着服务」时才会响。智能体在深夜、午休或你离开电脑时发来的请求，往往要等你回到电脑前才会被发现。

启用 ntfy 推送后，**由 RelayMesh 服务端直接把提醒发到 [ntfy](https://ntfy.sh)**：手机、电脑上订阅了同一个主题的 ntfy 应用会立刻收到通知，不依赖任何网页是否打开，手机锁屏也能收到。

- 默认**关闭**，只有你在设置里启用并保存后才会向外发送任何内容；
- 默认只在一种情况下推送：**智能体发起了新的反馈请求**（有人需要你回复）；另有一个**可选**的推送——模型经 ExecMesh 在主机上跑的命令**跑完**时通知你（同样默认关闭，见「[模型命令跑完时的推送](#模型命令跑完时的推送可选默认关闭)」）；
- 默认只发会话标题、项目名和主机名，**不含智能体汇报的正文**，更不含命令的输出；
- 推送失败不会影响智能体与 MCP 的任何功能，也不会拖慢命令的收尾。

## 快速开始（使用公共 ntfy.sh）

1. 在手机上安装 ntfy 应用（Android / iOS，也可以用网页版或桌面浏览器通知）。
2. 打开 RelayMesh 的 **设置 → 外观与通知 → 手机 / 桌面推送（ntfy）**。
3. 点主题右边的 **随机生成**。界面会显示「在 ntfy 应用里订阅」的地址，在 ntfy 应用里订阅**同一个主题**。
4. （可选）点「用当前地址」填好「点击通知后打开」的地址，点开通知就能直接回到控制台。
5. 点 **发送测试推送**，手机上收到「RelayMesh 测试推送」就说明通了。测试会直接使用你正在填写的内容，不必先保存。
6. 打开「启用 ntfy 推送」并点 **保存**。

> **公共 ntfy.sh 上，主题名就是口令。** 知道主题名的人可以订阅到你的推送，所以一定用「随机生成」的长名字，不要分享、不要截图外传。涉及敏感信息的项目，请自建 ntfy 并开启访问控制（见下）。

## 自建 ntfy 与访问控制

服务地址填你自建实例的地址（可以带路径前缀，例如 `https://example.com/ntfy`）。**Hub 所在的机器必须能访问到它**——推送是服务端发出的，不是浏览器发出的。

如果你的 ntfy 开了访问控制，在「认证方式」里选一种：

| 认证方式 | 适用 | 说明 |
|---|---|---|
| 无认证 | 公共 ntfy.sh、没开访问控制的自建实例 | 默认 |
| 访问令牌 | 自建或付费账号 | 填 ntfy 的 `tk_` 开头的访问令牌（推荐） |
| 用户名与密码 | 自建且用账号密码控制访问 | 用户名里不能有冒号 |

要点：

- **凭据只写不读**：保存后，接口、页面、日志里都不会再出现令牌或密码；输入框留空表示「保持不变」，填写则替换。要清除，换成「无认证」再保存。
- **也可以用环境变量提供令牌**：设置 `RELAYMESH_NTFY_TOKEN` 后，它优先于界面里保存的令牌，界面会提示「由环境变量提供」，也无法在界面里清除。适合不想把令牌放进数据库的部署（例如 Docker secrets）。
- 令牌和密码保存在服务端数据库的系统设置里，保护级别与 JWT 密钥相同、**没有额外加密**；备份数据库文件时请按敏感文件对待。
- 使用 `http://` 并带令牌 / 密码时，凭据是明文传输的，界面会给出提醒。回环地址与内网地址不提醒。

## 推送的内容

下表是「智能体在等你回复」的推送；模型命令跑完的推送内容见下一节。

| 项目 | 内容 |
|---|---|
| 标题 | 「智能体在等你回复」 |
| 正文 | 第一行是会话标题，随后是「项目：…　主机：…」 |
| 摘要 | 默认**不含**。打开「通知里附带摘要开头」后，正文里附上智能体汇报的前 160 个字（已去掉 Markdown 标记与代码块） |
| 点击通知 | 打开你填写的「点击通知后打开」地址（可选） |
| 优先级 | 默认「较高（4）」，可在 1～5 之间选；ntfy 据此决定是否响铃、是否穿透勿扰 |
| 图标标签 | `speech_balloon` |

> 打开「附带摘要」后，摘要会经过 ntfy 服务。使用公共 ntfy.sh 时它就是第三方服务，界面会提醒；涉及敏感信息的项目建议保持关闭，或者自建。

## 模型命令跑完时的推送（可选，默认关闭）

模型经 ExecMesh 在主机上提交的命令可能要跑几十分钟甚至几天（单条命令上限 7 天）。打开 **「模型命令跑完时推送」** 后，命令一结束就会推送一条结果，不必守在网页前。

- 开关在同一个设置区块里，**默认关闭**，与「智能体需要你回复」的推送互相独立；
- **只推送「跑够了一定时间」的命令**：「只推送运行时间不少于」默认 1 分钟，可在界面里选 30 秒～1 小时（接口可设 1 秒～1 天）。很快就结束的命令不会打扰你；
- 命令结束就是确定的事实，没有「你已经在网页上处理掉」一说，所以**不受「推送时机」延迟的影响**，结束后立即发出。

| 命令的结果 | 推送标题 | 说明 |
|---|---|---|
| 成功 | 模型命令已完成 | 优先级最高压到「默认（3）」，好消息不会穿透勿扰 |
| 失败 | 模型命令失败（退出码 N）／模型命令被信号终止（SIG） | 用你设置的优先级 |
| 超时 | 模型命令超时，已被终止 | 命令超过自己的 `timeout_seconds` 被终止 |
| 结果丢失 | 模型命令的结果已丢失 | 主机重启或守护进程消失，无法确认结果 |
| 被中断 | 模型命令被中断 | 主机上的会话守护进程被停止或重启，把运行中的命令一起终止了；正文写明原因 |

**不会推送**的情形：

- 你在网页上取消、暂停或撤销授权、系统取消、模型自己取消的运行——这些都是有人主动的操作，你已经知道了；
- 等待批准、被拒绝的命令——它们没有「跑完」。

正文包含：命令描述（模型写的一句话）、主机（优先用你在主机页起的备注名，不是机器码）、项目、用时，失败或被中断时再加一行原因。**绝不包含命令的输出**；命令本身默认也不带，只有打开「通知里附带摘要开头」后才会附上命令的**第一行**。

> 命令描述由模型书写，可能带有项目信息；使用公共 ntfy.sh 时它会经过第三方服务（界面同样会提醒）。涉及敏感信息的项目，请自建 ntfy 或保持这个开关关闭。

运行结束的推送与上面的推送共用同一套去重（同一次运行只推一次）、限流、失败重试和状态统计。

## 推送时机：立即或延迟

「推送时机」默认是**立即推送**。也可以选 30 秒、1 分钟、2 分钟、5 分钟：

- 这段时间里你已经在网页上处理了这条请求（回复、取消等），**就不再推送**，不会为一件已经办完的事打扰手机；
- 到点时服务端会重新检查：请求仍在等待、并且推送开关仍然开着，才会发出。
- 延迟中的推送只保存在服务端内存里，服务重启会丢失（此时请求本身也已中断）。

## 防打扰与可靠性

- **去重**：同一条请求（或同一次命令运行）在 10 分钟内只推送一次，智能体断线重连不会反复提醒。
- **限流**：每分钟最多推送 20 条（请求推送与命令运行推送合计）；超出的不再逐条发送，合并成下一条消息里的一句「另有 N 条通知因推送过于频繁被合并，请到控制台查看」。
- **失败重试**：网络错误、ntfy 服务的 5xx 与 429 限流会重试（间隔约 1 秒、4 秒；若服务返回 `Retry-After` 且不超过 15 秒则遵从）；认证失败、地址错误等 4xx **不会**重试，立刻在界面里报告原因。
- **不阻塞**：推送在后台队列里异步发送，队列满了会丢弃并计入统计，绝不会拖慢智能体的请求。
- **状态可见**：设置页底部显示「最近一次推送」是否成功、失败原因，以及累计推送 / 失败 / 被限流合并的条数（这些数字只存在内存里，服务重启后清零）。

## 安全边界

- 推送地址由管理员在设置里填写，服务端在**连接时**检查实际解析到的地址：拒绝链路本地地址（含云厂商元数据地址 `169.254.169.254`）、IPv6 链路本地、未指定地址与组播地址，防止被用来探测云环境。回环地址与内网地址**允许**，以便使用自建的内网 ntfy。
- 不跟随重定向（避免被引到别处）；遇到重定向会提示把服务地址改成最终地址（例如把 `http://` 改成 `https://`）。
- `https://` 的服务校验证书；自签名或域名不符的证书会报错并给出提示，请换用受信任的证书，或在内网使用 `http://`。
- 错误信息会抹掉令牌与密码、去掉控制字符，也不包含主题与完整地址；服务端日志里只记录主机名。
- 配置接口都需要登录；测试推送接口每 2 秒最多一次。

## 常见问题

| 界面提示 | 原因与处理 |
|---|---|
| 认证失败（HTTP 401 / 403） | 令牌或用户名密码不对，或它们对这个主题没有发布权限。提示末尾会附上 ntfy 返回的说明 |
| 找不到发布接口（HTTP 404） | 服务地址不对：检查路径前缀，以及它是不是真的指向 ntfy |
| 服务不接受发布请求（HTTP 405） | 地址指向的不是 ntfy，或 ntfy 版本太旧、不支持 JSON 发布 |
| 服务返回了重定向 | 把服务地址改成最终地址（常见是 `http://` 要改 `https://`） |
| 推送太频繁，被 ntfy 服务限流（HTTP 429） | 公共 ntfy.sh 有速率限制；稍后再试，或自建 |
| 连接 ntfy 服务超时 / 失败 | Hub 所在机器访问不到该地址；检查网络、防火墙、代理 |
| 无法解析服务地址的主机名 | 域名拼写或 DNS 问题 |
| TLS 证书校验失败 | 证书不受信任或与域名不符 |
| 服务地址解析到了被禁止的地址 | 地址指向链路本地 / 元数据 / 组播地址，不允许 |

排查顺序：先点「发送测试推送」看界面给出的原因；测试通过但真实请求没有推送时，检查是否启用并保存、是否选了延迟、请求是否已被你在网页上处理掉。

命令跑完却没有收到推送时，依次看：「模型命令跑完时推送」是否打开并保存；命令的运行时间是否达到「只推送运行时间不少于」的门槛；这次运行是不是被你、模型或系统取消的（这类不推送）；是否被限流合并了（设置页底部「被限流合并」的计数会增加）。

iOS 上自建 ntfy 想要即时收到推送，需要在 ntfy 服务端配置转发到 ntfy.sh（`upstream-base-url`），详见 [ntfy 官方文档](https://docs.ntfy.sh/config/)里关于 iOS 的说明。

## 接口（供脚本使用）

三个接口都在 `/api/v1/notify/ntfy` 下，需要网页登录令牌：

| 方法与路径 | 作用 |
|---|---|
| `GET /api/v1/notify/ntfy` | 读取配置与最近状态。凭据只返回 `token_set` / `password_set` / `token_from_env` 三个布尔值 |
| `PUT /api/v1/notify/ntfy` | 保存配置。普通字段整体替换；`token` / `password` 留空表示保持不变；`clear_token` / `clear_password` 为 `true` 时清除；清空 `username` 会一并清除密码 |
| `POST /api/v1/notify/ntfy/test` | 发送一条测试推送。请求体可选 `{"draft": {…}}`，把尚未保存的配置叠加在已保存配置上试发；返回 `ok`、`attempts`、`took_ms`、`http_status`、`error` 与最新状态 |

字段范围：`topic` 由字母、数字、下划线、连字符组成且不超过 64 个字符；`server` 必须以 `http://` 或 `https://` 开头，不能带用户名、查询串或片段；`priority` 为 1～5；`delay_seconds` 为 0～900（只作用于「等你回复」的请求推送）。启用时 `topic` 必填；未启用时允许保存只填了一半的配置。

「模型命令跑完时推送」对应两个字段：`run_notify`（布尔，默认 `false`；因为普通字段是整体替换，保存时不带它就等于关闭）与 `run_min_seconds`（整数 1～86400，默认 60；不带或为 0 时按 60 处理，旧版本保存的配置读出时同样补上默认值）。它们只在 `enabled` 为 `true` 时才会真正发出推送。

## 与环境变量

| 环境变量 | 说明 |
|---|---|
| `RELAYMESH_NTFY_TOKEN` | ntfy 访问令牌。设置后优先于界面里保存的令牌，并显示「由环境变量提供」 |

其余配置（服务地址、主题、点击地址、优先级、延迟、是否附带摘要、是否推送命令跑完、最短运行时长、用户名）都在设置页里管理，保存在服务端，所有浏览器共享同一份。
