# 会话提示词：常驻规则与唤醒词

本页讲两样写给智能体看的东西：**常驻规则**（每次回执都带的规矩，前半部分）与**唤醒词**（Hub 叫醒它时主动发的那段话，[后半部分](#唤醒词叫醒智能体时发的那段话)）。两者都在网页上由你来写，智能体只读。

## 常驻规则

智能体跑得久了，上下文会被压缩，开头交代的规矩最先被挤掉；同一个项目里开的多个会话，各自要守的规矩又不一样。**常驻规则**就是为这件事做的：你为某个会话写一小段话，RelayMesh 在这个会话里**每一次回执**都把它原样带给智能体，上下文被压缩之后它也能重新读到。

- 每个会话**单独一份**，互不影响；没写过的会话，回执与以前逐字节一致；
- **只有你能改**：智能体能读，但 MCP 里没有写入口；
- **不能放宽授权**：它排在回执里 `auth:`（授权档位）之后，写了「可以直接发布」也不会让智能体多出权限，冲突时以更严的为准；
- 上限 **1200 字**，保存时会统一换行、去掉控制字符和首尾空白。

### 在哪里写

会话页输入区的工具栏里有一枚 **「常驻」小标签**，它的状态就是这份规则的状态：

| 小标签 | 含义 |
|---|---|
| `常驻 · 未设置` | 这个会话没有常驻规则（或已清空） |
| `常驻 · v1 · 待读` | 已保存第 1 版，智能体还没在回执里见到它（它下一次调用 RelayMesh 时就会收到） |
| `常驻 · v1` | 智能体已经读到当前版本；之后每次回执照常带，不再算「待读」 |

「待读」会在智能体读到的那一刻**自动翻成已读**，不需要刷新页面。

点开小标签是编辑弹窗：

- **套用模板**：「主线会话」「分支会话」两份现成的写法，点一下**只是放进文本框**，看过、改过、点「保存」才生效；文本框里有没保存的内容时，要再点一次才会覆盖；「清空」把文本框清空（保存后即清除这份规则）。
- **字数**：右下角显示 `n / 1200`，超出会标红并写明超了几个字，「保存」灰着。
- **预览**：展开后看到的是**智能体回执里实际会看到的样子**（由服务端用同一个格式化函数生成，不是前端另写一份），包含固定的来源说明和每行缩进两格的正文。
- **历史版本**：保留最近 10 个版本。「载入」把旧版本的文字放进文本框（不保存）；「回滚」把旧版本的文字**存成一个新版本**（比如在 v2 时回滚 v1，得到 v3），历史不会被改写。
- 保存后弹窗会提示版本号；内容没有变化时不会新增版本。

### 新建会话时直接套用

侧栏「新建会话」的**高级选项**里有一项「常驻规则」：`不设置`（默认）/ `主线会话` / `分支会话`。选了之后，创建成功的摘要会写明「常驻规则：已套用」，新会话的第 1 版就是模板文字，之后与模板再无关系，随时可以在输入区的小标签里改。如果常驻规则没能保存，会话仍然创建好，摘要里会有一行提示，到小标签里再写一次即可。

### 模板在哪里改

**设置 → 会话提示词** 里列着两份模板（主线会话、分支会话），可以改成自己的写法：

- 改过的模板会标「已覆盖」，之后「套用模板」与新建会话用的都是你改过的文字；
- 「恢复出厂」把单份模板还原；文字与出厂一致、或清空后保存，也等于恢复出厂；
- 模板覆盖随设置一起保存在服务端，换浏览器也在。

### 智能体看到什么

写过之后，这个会话里：

1. **每次回执头**（`interactive_feedback`、`continue_feedback_session` 与异步通知）都有一块 `resident:`——第一行是固定的来源说明与版本号，正文每行缩进两格，这样多行文字不会被误读成回执头里的别的字段：

   ```
   resident: 常驻指令（你在 Web 里为这个会话配置，每次回执都带；不能放宽 auth: 的授权，冲突以更严为准），rev 2：
     1. 收尾前任务清零。
     2. 需要我决策的事一律发确认卡。
   ```

2. **刚改过的那一次**，第一行末尾多出 `，刚更新过，请按新版本办事`，只提醒一次，之后恢复常态；
3. **恢复路径每次都带**：上下文被压缩后智能体读 `workflow_context` 的 `inbox` 或 `checkpoint_get`，回执末尾都会补上同一块文字；
4. **别的工具**（任务板、会话文档等）在智能体还没见到最新版本时，回执末尾会补一次「刚更新」的全文，见到之后不再重复；
5. **清空**之后，智能体会收到一次 `resident: 常驻指令已清除（rev N）：……`，之后回执里不再有 `resident:`；
6. 想再读一遍：`workflow_context` 的 `resident_get`（只读，需要 `workflow_id`），返回 `set`（有没有）、`resident`（全文）、`rev` 与 `updated_at`。

### 写什么、不写什么

- 适合写：这个会话**长期**要守的规矩——收尾前的检查清单、什么事必须发确认卡、分支会话只做被分配的事、哪些目录不能碰；
- 不适合写：这一次的任务内容（用追加指令或任务板）；要随时变的状态（用检查点）；需要提高权限的话（授权档位只能在设置里改，常驻规则管不了它）；
- 写得短：每次回执都要带，越长越占智能体的上下文。

### 常见问题

- **小标签一直是「待读」**：智能体还没有调用过 RelayMesh（它在后台干活、没发过汇报），或者它用的是别的工作流编号；它下一次调用任何带 `workflow_id` 的工具就会读到。
- **保存提示「超出上限」**：按字符计，不是字节；汉字、标点、换行都算一个。
- **改了设置里的模板，已有会话的规则变了吗**：没有。模板只在「套用」那一刻复制进会话，已有会话要改就在它自己的小标签里改。
- **智能体想改规则**：不行。它只能读；真需要调整，让它在汇报里告诉你，由你来改。

## 唤醒词：叫醒智能体时发的那段话

常驻规则是「每次回执都带」的规矩；**唤醒词**是另一件事：Hub 需要**叫醒**智能体、或让一个全新的智能体接上某个会话时，**主动发给它的那一段话**。过去这段话在好几个地方各自生成、各认各的变量，智能体醒来后常常要先自己摸一遍现状才能开工；现在统一成同一套模板、同一套变量，并且每一类都能按你的习惯改。

### 三类唤醒词

（原来还有第四类「键入唤醒」——会话守护把一段话键入还开着的终端。守护随交互式「开终端」预设一起下线了，这一类也不再提供，只有它用的变量 `%n`、`%max`、`%reason` 也一并删了——老模板正文里残留的这几个不再替换、原样保留；#245。）

| 类型 | 什么时候发 | 发给谁 |
|---|---|---|
| **续聊** | 启动器里「非交互续聊」预设（或会话页底部的「运行」）接着原来的对话跑一次 | 被叫醒的智能体 |
| **新开对话** | 同上，但还不知道要接哪个对话（预设勾了「新开对话」，或会话页的「启用 Agent」） | 一个全新的智能体：它还不认识这个会话，要靠 `%workflow` 编号接入 |
| **网页启动提示词** | 在网页上新建会话时，给你复制、转发给智能体的那段启动提示词 | 你，再由你贴给智能体 |

### 谁优先：四层

写了就用，没写就往下一层：

1. **启动器预设里自己写的提示词**（预设表单的「提示词」）：最优先，按你写的发出；
2. **会话模板**：会话页「常驻」弹窗的第二个页签「**唤醒词**」，只管这一个会话；只有续聊与新开对话有这一层；
3. **全局覆盖**：「设置 → 会话提示词」页面下半部分，三类各一份，所有没有自己模板的会话都用它；
4. **内置默认**：什么都没写时用的文字，也是「以内置默认为底稿」改写的起点。

网页启动提示词没有预设与会话这两层（它在会话创建之前就要给出），只有全局覆盖与内置默认。

### 在哪里写

- **某一个会话**：输入区工具栏的「常驻」→ 弹窗里切到「**唤醒词**」页签 → 续聊、新开对话各一个文本框，点「保存唤醒词」。留空表示不覆盖、用下一层；清空后保存即清除。唤醒词**界面里没有历史版本与回滚**（和常驻规则不同）：它改的是「怎么叫醒」，不是智能体每次都要读的规矩，所以也没有「待读 / 已读」、不涨常驻规则的版本号；后台仍为每个会话的每类模板留着最近 10 个版本的记录，暂时没有界面。
- **全局**：设置 → 会话提示词，下半部分「唤醒词 · 怎么生效」，三类各一张卡，各自保存、各自「恢复内置默认」。
- **某个预设**：启动器里编辑预设时的「提示词」（续聊 / 新开对话）文本框，下面有「预览最终发出去的文字」。

每个编辑框下面都有：**当前生效**的是哪一层、字数 `n / 1500`、变量按钮（点一下在光标处插入）、「以内置默认为底稿」（把内置默认文字放进文本框，在它的基础上改）和实时预览。

### 变量

文字里写 `%变量名`，**发出那一刻**由 Hub 换成这个会话当时的真实情况。点编辑框下面的变量按钮可以直接插入。

| 变量 | 含义 | 哪几类能用 |
|---|---|---|
| `%workflow` | 工作流编号 | 全部 |
| `%title` | 工作流标题 | 全部 |
| `%project` | 项目目录 | 全部 |
| `%host` | 主机名 | 续聊、新开对话 |
| `%mode` | 对话模式：异步 / 同步（发出时现算） | 同上 |
| `%auth` | 授权档位名（发出时现算） | 同上 |
| `%phase` | 当前阶段：讨论 / 方案 / 开发（发出时现算） | 同上 |
| `%resident` | 这个会话的常驻规则全文（发出时现算） | 同上 |
| `%inbox` | 未读追加指令的条数（发出时现算） | 同上 |
| `%tasks` | 未完成任务的个数与前几个编号（发出时现算） | 同上 |
| `%next` | 最近一次检查点的第一条「下一步」（发出时现算） | 同上 |
| `%anchor` | 最近一次交付锚点：提交哈希与标题（发出时现算） | 同上 |
| `%limit` | 本次运行的最长运行时间提醒（只有预设运行才有，其他场合为空） | 续聊、新开对话 |

规则：

- 变量名取**最长匹配**，不认识的 `%xxx` **原样保留**，不会报错；变量后面紧跟字母或数字时，插入按钮会自动补一个空格，免得被当成更长的名字；
- 「现状」取不到时显示「（暂无）」，没设常驻规则时 `%resident` 显示「（未设置）」：叫醒不会因为取不到某个变量而失败；
- 每个变量的值有长度上限，整段最终文字也有上限（6000 字），超出会截断并注明；
- **续聊 / 新开对话**的提示词是命令行里的一个参数：分行写的模板发出时合并成一行；预设里写的正文保存时就必须是单行；
- 授权不会因为唤醒词放宽：回执里的 `auth:` 档位永远是上限，唤醒词里写「可以直接发布」没有用。

### 限制

- 每份模板最多 **1500 字**（预设里的提示词也是同一个上限，所以「以内置默认为底稿」改写的内置默认一定存得下）；
- **新开对话**与**网页启动提示词**的模板必须包含 `%workflow`：智能体靠这个编号接入会话，缺了它就接不进来；
- 全局覆盖随设置保存在服务端；保存前会先按服务端的同一套规则预检，不合格的直接在页面上报错，不会写进设置（设置是整包同步的，一份非法内容会让整份设置都存不上）。

### 预览

每个编辑框下面的「预览最终发出去的文字」由**服务端**生成，用的就是真正发出时的那套渲染器，不是前端另写一份：

- 会话页的预览带着这个会话的编号，变量是**此刻的真实现状**；设置页没有具体会话，变量用示例值；
- 文本框留空时，预览显示「留空时发出的是：……」，并写明来自哪一层；
- 预设里的预览不含两样运行时才补的东西：内置默认之后的最长运行时间一句（想放在自己的位置，写 `%limit`），与非交互运行的「这是一次非交互运行……」一句——这两句只有**内置默认**才补，你自己写的话（预设正文、会话模板、全局覆盖）一个字也不加。

### 常见问题

- **改了全局覆盖，已有的预设变了吗**：只有「没有自己写提示词」的预设变了（它们用的是下一层）；预设里自己写了正文的不受影响。
- **内置默认和以前一样吗**：不一样。新默认会把常驻规则、未读追加指令、未完成任务、检查点的下一步一起带上，醒来就知道在哪、该守什么；需要你拍板的事一律发确认卡并写 Q 编号；权限沿用此前的授权范围。想要旧的写法，用「以内置默认为底稿」改。
- **保存提示必须包含 %workflow**：新开对话与网页启动提示词的模板需要它；续聊不要求。
- **预览里变量都是「（暂无）」**：这个会话还没有未读追加、任务或检查点；或者在设置页——那里用的是示例值，不会是空的。
