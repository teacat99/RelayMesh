# 异步对话模式：发完进度就继续干活

默认情况下，智能体每做完一段就用 `interactive_feedback` 汇报，然后**停下来等你回复**——对话是同步的，你不在，它就干等。

**异步对话模式**把这件事改成「发完进度就继续」：

- 智能体用 `interactive_feedback` 加 **`wait:false`** 发布进度、阶段结论和对你的回答，**立即返回**，不再停下来等；
- 你的追加与答复，由 **hook** 在智能体两次工具调用之间送到它手里（见 [docs/inbox.md](inbox.md)）；
- 需要你拍板的事走 `async_ask`（见 [docs/confirm-items.md](confirm-items.md)），大改动先提交**计划确认**；
- 原来的「讨论 / 方案 / 开发」阶段提示词让位给**授权档位**：智能体不必先问、能直接做到哪一步，由你选的档位决定；
- **部署、推送远端、删数据、改凭据、不可逆迁移（L2）在任何情况下都要你批准才会执行**：智能体发一张 **L2 确认卡**（`async_ask`，`risk:"L2"`），不阻断其余工作，**批准前绝不执行这一步，没有答复就是不批准**——没有「放飞」一档。

它是**按工作流**开启的，默认关闭；从没开过的工作流，一切与以前逐字节一致。

## 怎么开启与关闭

1. 先给这个项目装好编辑器 hook（会话页工具栏里的 hook 芯片，点开有现成的安装命令）。异步对话靠 hook 才能在智能体工作时把你的话送过去，所以**这个工作流收到过 hook 事件之前，开关是灰的**，REST 开启也会被 409 拒绝，说明里指向安装 hook。
2. 点开 hook 芯片，弹层里的「异步对话」开关打开即可。状态一行写明：**已生效** / **已开启，暂未生效**（并写原因）/ **已关闭** / **未开启**。
3. 生效后，工具栏上的阶段滑块换成「**授权：标准授权 L1**」小标签；点开可以给这个工作流换档，或进设置管理档位。
4. 想退回原来的逐条确认：再点一下开关。**关闭永远允许**，阶段滑块随即回来，已发布的进度气泡留在时间线上。

### 什么时候「已开启，暂未生效」

异步是否生效 = **你开着** 且 **最近 60 分钟内见过这个工作流的 hook 事件**。不满足时自动按同步工作，回执头写明原因，hook 回来后自动恢复生效：

| 原因 | 含义 |
|---|---|
| `disabled` | 你开启过、现在关了 |
| `no_hook` | 开着，但这个工作流还没见过 hook |
| `hook_stale` | 开着，但 hook 已超过 60 分钟没有出现——追加与答复可能送不到，此时让智能体「发了就走」会没人听见 |

注意：hook 的「最近出现」热路径只读写内存，同时**每个工作流最多每分钟落库一次**，Hub 启动时装回来——所以重启（包括热更新）之后，只要重启前 60 分钟内见过 hook，异步就继续有效，不必等 hook 再来一次。恢复出来的就是重启前本来会有的那个时间（最多偏旧一分钟），**没有额外宽限期**：Hub 停了很久再起来，照旧按 `hook_stale` 降级。

## 智能体侧

### 回执头里的三类行

只有**开启过异步**的工作流，回执头才会多出这几行（`interactive_feedback`、`continue_feedback_session` 的回执头，以及 `set_phase` 的返回里）：

| 行 | 内容 |
|---|---|
| `mode:` | `mode: async`（生效）或 `mode: sync（原因）`（开启过、现在是同步） |
| `async:` | 生效时的行为契约（不超过 760 字）：进度用 `wait:false`，汇报只讲进展与结论，**凡是在等你答复或拍板的事，一律发成确认卡（`async_ask`），不只写在汇报里**，避免被漏看；有默认值且可回滚的事用 `async_ask`，大改动先提交计划；追加与答复经 hook 与 `inbox` 送达；**L2 发确认卡（`async_ask` 的 `risk:"L2"`）、不停下来等，批准前绝不执行、没有答复就是不批准**（档位已明确授权的推私有库、热更生产除外）；**收尾：非阻断任务先做完，等用户拍板的置「暂缓」**；长耗时命令（构建、测试、e2e、部署）默认后台启动，等待时先做不依赖结果的事，等待只用计时器分片（每片 ≤2 分钟），片间读收件箱 |
| `auth:` | 生效时当前档位的名称、等级与规则（不超过 300 字），**取代**阶段提示词 `phase_prompt` |

没开过异步的工作流没有这些行；同步回执有一份金样测试（`internal/mcp/sync_golden_test.go` 与 `testdata/sync_receipts.golden`）逐字固定，改异步相关代码不能让它变。

用户**切换模式、换档、改了档位规则、删掉选用中的档位（回落到默认）**之后，智能体不会靠猜：下一次工具调用的返回末尾会多一段以 `mode:` 开头的说明，**只提醒一次**。

### `wait:false`：不阻塞的进度通知

`interactive_feedback` 多了一个 `wait` 参数：

- 只有**明确写成 false**（`false` / `"false"` / `0` / `"0"` / `"no"`）才算；缺省、`true`、空串、乱写一律按「照常等待」，宁可多等也不误放行；
- 工作流处于**有效的异步模式**时：发布一条**进度通知**，立即返回「已发布（不阻塞）」，回执头带 `mode` / `async` / `auth`；
- 否则**回退成普通的阻塞汇报**，回执头多一行 `wait_ignored:`，说明为什么没放行（没开启 / 已关闭 / 没见过 hook / hook 太久没动静 / 没传 `workflow_id`）；
- 必须显式传 `workflow_id`（异步是按工作流开启的）。

进度通知的性质：

- **不是一轮**：没有「第 N 轮」，不占轮次编号，时间线微缩轴与历史计数都不算它；
- **没有回复框**，不进「待确认」条，不触发声音 / ntfy 提醒（那是给「有人在等你」用的）；
- **不会吞掉你的追加**：你排在收件箱里的追加留着，等智能体读取；
- **限流**：每个工作流每小时最多 60 条，超出时报错并建议合并成一条；
- 在 `list_sessions` / `get_session_history` 里带 `kind: "notice"`，历史里的 `rounds` 不含通知；对通知调用 `continue_feedback_session` 会得到一句说明（它没有什么可等待的）。

### `set_phase`

异步生效时，`set_phase` 的返回不再带 `phase_prompt`，改为带 `mode: "async"` 与 `auth`。

### 收尾规则：非阻断任务做完才能结束会话（#124）

智能体想收尾（发总结、结束这一轮）之前：

- **不用等用户答复的任务**（待办、进行中、验证中）要先做完，置「已完成」并写结论；
- **必须等用户拍板才能继续的任务**置「暂缓」，并在进度里写明在等什么。暂缓的任务不算「在做」，**不挡回复窗口，也不挡收尾**，但收尾总结里要把它们列出来；
- 之后看回执里的 `window:` 行：窗口走完、收件箱为空，才收尾。

服务端怎么度量：回复窗口只在手头有「进行中 / 验证中」任务（近 3 小时内有更新）时暂停，**待办不计入**——待办靠上面这条规则约束智能体自己：要么做完，要么置「暂缓」并说明原因。

规则要避免两种失败：手头还有能做的事就收尾，逼用户再唤醒一次；一个其实在等用户的任务一直挂在「进行中」，窗口永远暂停、会话永远结束不了。

## 不可逆操作（L2）：发确认卡，批准前不执行（#217）

部署、推送远端、删数据、改凭据、不可逆迁移、发布这类**不可逆或高风险**的操作，异步对话里的做法是：

1. 智能体用 `async_ask` 发一张 **L2 确认卡**（`risk:"L2"`，选项通常是「批准 / 暂不」，**不能带 `default_option`**，服务端会拒绝），**不停下来等**，先去做不依赖它的事；
2. 卡片出现在待确认条里，带红色 L2 标记、排在最前；**只能逐张作答**，没有「采用推荐」，也不进批量；
3. 你的答复经收件箱送到智能体。**批准前它绝不执行这一步，没有答复就是不批准**；你选了「暂不」、写了自定义答复或答复含糊，都按未批准处理；
4. 收尾时还没批准：依赖它的任务置「暂缓」并写明在等 `Q12`；卡片**没有自动过期**，一直等到你回来作答；
5. 档位规则**明确授权**的推私有库、热更生产除外（直接做、做完汇报）；发布打 tag、同步公开库、删数据、改凭据等不在此列，仍然要发卡等你批准。

同步（默认）模式不变：L2 仍用阻塞式 `interactive_feedback` 等你明确答复。服务端替你守住的底线，以及「批准前不执行」要靠智能体守约这一点，见下面的「设计取舍与已知局限」。

## 授权档位

档位是**全局**的一张表，工作流各自选用，没选的跟随默认：

- 内置一档默认的「**标准授权**」（L1）：读与分析、跑测试、工作树内可回滚的改动与本地提交直接做；部署、推送远端、删数据、改凭据、不可逆迁移先发 L2 确认卡、批准前不执行；大改动先发计划确认卡；
- 你可以再加：名称（最多 24 字）、等级（**只有 L0「只读，写入先问」与 L1「可回滚的改动直接做」**）、规则摘要（最多 240 字，写给智能体看）。最多 12 档；
- 默认档位不能删；删掉某个工作流正在用的档位，它**回落到默认档位**，并经「mode 提醒」告知智能体一次；
- **没有 L2 一档**：不可逆操作不是可以授权出去的东西；
- 契约里「部署、推送远端……（L2）发确认卡」有一处让路：档位规则**明确写了**的可回滚交付动作（推私有库、热更生产）直接做、做完汇报。删数据、改凭据、不可逆迁移、发布打 tag、同步公开库不在此列，任何档位下都要发 L2 确认卡等你批准；默认的「标准授权」没有授权它们，所以仍然要批准。
- 升级前建的库里，默认档位若还是**逐字相同的旧出厂文案**（「…先用 interactive_feedback 阻塞确认…」），启动时会自动刷新成当前写法，免得 `auth:` 行与契约互相矛盾；你自己改过的规则不动——如果你的规则里写着「阻塞确认」，请改成「发 L2 确认卡」。

## 界面里能看到什么

- **hook 芯片弹层**：异步对话开关、状态说明、授权档位下拉、当前档位的规则；
- **授权小标签**（工具栏，生效时取代阶段滑块）：点开列出全部档位，点一下换档；「管理档位…」直达设置里的「授权档位」；
- **设置 → 授权档位**：新增 / 编辑 / 设为默认 / 删除（删除是两步确认）；
- **时间线上的进度气泡**：「智能体进度」，Markdown 渲染，按提交时间穿插在轮次之间；气泡上显示这条回复的短哈希，点一下就把「【回复 哈希】」引用插进输入框（见 [inbox.md](inbox.md#引用某条回复回复哈希)）。进度气泡本来就没有回复框，所以不再有「不用回复」这类没有信息量的标注；
- **任务更新卡**：开启异步之后任务每有一次进展（新建 / 进行中 / 待您验收 / 已完成 / 已搁置 / 只写了进度）就是一张，按提交时间落在对话里；连续的几张默认叠成一摞、点开看全部，点「查看」打开任务详情。只有开启过异步的工作流才有，同步工作流的时间线保持原样。

## 接口（仅 Web 登录令牌；MCP 令牌得 403）

| 方法与路径 | 说明 |
|---|---|
| `GET /api/v1/workflows/:wf/async-mode` | 这个工作流的异步状态：`enabled` / `ever_enabled` / `effective` / `mode` / `reason` / `can_enable` / `hook_last_seen_at` / `profile` 等 |
| `PUT /api/v1/workflows/:wf/async-mode` | `{enabled?, profile_id?}`；开启需要见过 hook，否则 409；档位不存在 404 |
| `GET /api/v1/auth-profiles` | 档位表、默认档位编号与长度上限 |
| `POST /api/v1/auth-profiles` | 新增档位 |
| `PUT` / `DELETE /api/v1/auth-profiles/:id` | 编辑 / 删除（默认档位不能删） |
| `POST /api/v1/auth-profiles/:id/default` | 设为默认档位 |

`GET /api/v1/workflows/:wf/inbox` 的返回里带 `async_mode`；SSE 事件 `workflow_mode_updated`（某工作流的开关或档位变了）与 `auth_profiles_updated`（档位表变了）让多个标签页同步。

## 设计取舍与已知局限

- **为什么按工作流、且要 hook**：异步的前提是「你的话能在它工作时送到」。没有 hook 通路的工作流开了异步，等于让智能体对着空气发言，所以硬性要求见过 hook，并在 hook 失联时自动降级。
- **L2 的底线不靠提示词，也不能说成「服务端保证了一切」**：服务端守住的是——L2 卡**不能带 `default_option`**（默认只能是「不做」）、**不进批量**、**不能一键采用推荐**、**没有自动过期**，而且**批准只可能来自你**（智能体没有任何作答确认项的工具）；`wait:false` 只能发通知、不能让一个需要你确认的动作「通过」；同题的 L1 卡也吞不掉 L2 请求（风险档算进「同一问题」的去重键）。**局限**：「批准前不执行」本身仍要靠智能体守约（动手的是它）——这一点与阻塞式 `interactive_feedback` 相同，所以契约第 4 条把它写给智能体，回执里也会再提醒一遍（`l2_notice`）。
- **hook 的新鲜度落库有节流**：热路径仍只读写内存（hook 每十几秒来一次，不值得次次写库），每个工作流最多每分钟落库一次（表 `workflow_hook_seens`），启动时恢复；落库值最多比真实值旧一分钟，所以恢复后只会偏旧、不会偏新，没有给异步多送宽限期。落库失败只意味着重启后恢复得更旧，不影响当前进程（#103）。
- **只有通知、没有轮次的工作流**：时间线上只有进度气泡，没有「第 N 轮」，这是预期的。
- **自动唤醒不在这里**：智能体停摆后的自动恢复属于会话守护，不属于异步对话模式。
