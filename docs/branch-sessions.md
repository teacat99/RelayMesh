# 分支会话

一件事干到一半，常常要岔出去另做一块：查一个缓存方案、试一种迁移写法、让另一个 Agent 并行改前端。把这些都塞进同一个会话，历史会越来越长、互相干扰；各开各的独立会话，又彼此不知道对方的存在。

**分支会话**就是把「岔出去的那一块」做成一个**独立的会话**——有自己的 `workflow_id`、自己的 Agent、自己的对话历史，你可以直接在网页里跟它说话——同时让它和原来的会话（**主会话**）保持联系：分支能向主会话汇报和请示，主会话能看到分支的进展、在你允许的范围内给它发话，也能替它定夺请示（定夺不了的转交给你）。

它**不是子 Agent**：分支里干活的是另一个 Agent（或另一个对话窗口），不是主会话的 Agent 派生出来的线程；两边互相发的是「同伴消息」，不是用户指令，与你的要求冲突时永远以你为准。

## 关系规则

- **一层**：分支不能再有分支；已经有分支的会话不能再做别人的分支。
- **一个分支只有一个主会话**。要换主会话，先用运维命令 `branch-unlink` 解除（见下文）。
- **数量**：一个主会话同时最多 8 个活动分支；每小时最多新建 5 个（防止脚本或 Agent 失控地开分支）。
- **结束**：结束分支只是改状态，关系和两边的历史都保留，你仍然能在网页里查看；结束后主会话不能再给它发话、也读不了它的历史。已结束的分支可以重新连回同一个主会话。
- 分支关系**不改变**两个会话各自的凭据、项目目录、阶段、常驻规则与任务板；它只是在两个会话之间多了一条沟通渠道。

## 向主会话开放什么

每个分支有一份「向主会话开放的范围」，**只有你能改**（主会话和分支的 Agent 都改不了）：

| 预设 | 主会话能读到分支的历史 | 主会话能给分支发话 | 主会话能替分支定夺请示 | 主会话能改分支的参数 | 主会话能启动分支 | 主会话能给分支派任务 | 适用 |
|---|---|---|---|---|---|---|---|
| `visible`（仅可见） | 每轮汇报的摘要（一行） | 不能 | 不能 | 不能 | 不能 | 不能（任务只读） | 让主会话知情，但不干涉 |
| `collab`（协作，网页新建时的默认） | 每轮汇报的全文 | 能 | 能 | 常驻规则 | 不能 | 能（还要两边在同一张任务板上，见下文「主会话给分支派任务」） | 两边紧密配合 |
| `managed`（托管） | 全文 | 能 | 能 | 全部参数（常驻规则、阶段、标题、唤醒词、异步开关） | 能（还要先有指向它的续聊预设，见下文「主会话唤醒分支」） | 能（同上） | 主会话统一调度，包括在分支停下来之后唤醒它 |

当前版本真正生效的是「读历史」「发话」「定夺请示」「改参数」「启动」与「任务」六项。「任务」只有两个取值：只读（`read`）与派单（`assign`），决定主会话的智能体能不能把**它自己建的任务**指派给这个分支（见下文「主会话给分支派任务」）；它是放宽任务权限的一项，但**打开它不需要再验证密码**，因为主会话能做的只是把自己的任务放进分支的待办，分支接取与否仍由分支决定。**分支向主会话发话永远允许**——分支需要请示、汇报时，不该被开放范围拦住。

### 「改参数」的四个档位

「改参数」是一个**档位**，由你在网页里设定，越往下能改的越多：

| 档位 | 主会话的智能体能改分支的什么 |
|---|---|
| `off`（不可改） | 什么都不能改，也读不到分支的参数值 |
| `resident`（常驻规则） | 分支的常驻规则（每一轮汇报都会带上的那段话，最多 1200 字） |
| `resident_phase`（常驻规则 + 阶段） | 再加上阶段（讨论 / 方案 / 开发） |
| `all`（全部参数） | 再加上标题、两条唤醒提示词、异步开关（只能关闭，或恢复你以前开过的状态；第一次开启永远是你的事） |

无论哪个档位，主会话**都改不了**档位本身、分支的授权（权限位、凭据）、项目目录与主机、终端访问。权限在**每一次调用时**重新检查：你把档位调低，主会话的下一次修改就会被拒。具体怎么改见下文「`session_params` 工具」。

**放宽要验证密码，收紧不要。** 把「改参数」档位调高、或把「启动」从关打开（含新建时选了带这两项的预设：协作带「改参数」，托管两项都带），要再输入一次 Web 密码（与终端解锁是同一套，已经解锁则不用再输）；调低、关掉「启动」、撤销主会话的修改、改其余设置（含打开或关掉「任务」派单），只要登录。终端总闸关着（没设 Web 密码、密钥偏弱，或 `RELAYMESH_TERMINAL=off`）时没法验证密码：放宽的项会被**压回原值**（「改参数」回到原档位，「启动」保持关闭），其余设置照常保存，界面写明哪一项没有放宽、为什么——不会因此整次保存失败。智能体用 `branch(action: "create")` 新建的分支一律是协作预设（主会话只能改常驻规则），这一步不需要密码；要给更大的权限，仍然只能由你在网页里放宽。

## 智能体怎么用：`branch` 工具

需要 `feedback` 或 `sessions` 权限位（与 `chat` 同一档）。必填 `workflow_id`（你自己的），`action` 缺省为 `list`。

| action | 谁能用 | 作用 |
|---|---|---|
| `list` | 任何人 | 看自己的角色：`main`（附每个活动分支的标题、最近活动、是否在等你回复、还有几条没读的消息、智能体状态 `agent_state`、还没做完的任务数 `open_tasks`、启动方式 `launch`（见下文「主会话唤醒分支」）、派单概况 `assign`（见下文「主会话给分支派任务」）、它向你开放什么，以及 `pending_asks`：分支送来、还在等你定夺的请示）、`branch`（附主会话是谁、你向它开放什么；主会话能给你派任务时，还有一段 `tasks_from_main` 告诉你怎么接取与交付）或 `none` |
| `create` + `title` | 任何没有「分支身份」的会话 | 新建一个分支会话，返回 `branch`（它的 `workflow_id`）与 `start_prompt`。把 `start_prompt` 交给将要在分支里干活的 Agent，或请你在新窗口里启动它；它用这个 `workflow_id` 连上 RelayMesh 就算入伙。默认开放范围是协作预设 |
| `say` + `text` | 主会话 ↔ 分支 | 给对方发一条消息（≤ 4000 字），落进对方的收件箱；**不阻塞、不用等回复**。分支发给主会话恒允许；主会话发给分支要求该分支开放了「发话」。有多个活动分支时用 `branch` 参数指明发给哪一个 |
| `read` + `branch`、`limit` | 主会话 | 读某个分支最近的几轮汇报（缺省 10 轮、最多 20）。深度按分支开放的范围：摘要档每轮一行，全文档给全文（不含图片），关闭则被拒并说明原因 |
| `answer` + `branch`、`ref`，加 `options`（选项编号）或 `text`（自己写的答复），可附 `note` | 主会话 | 替分支定夺一项还没答复的请示（见下文「决策路由」）。只能答「分支请示」（它们会作为「分支请示」落进你的收件箱），而且要求该分支开放了「定夺请示」 |
| `escalate` + `branch`、`ref`、`note` | 主会话 | 你定夺不了的请示（含不可逆、或需要用户本人批准的事）转交给用户；`note`（必填，≤ 300 字）写清为什么，用户在卡上看得到 |
| `close` + `branch` | 主会话 | 结束这个分支；还没答复的请示立刻转交给用户；分支的 Agent 会在收件箱里收到收尾通知；你派给它、还没交付的任务退回你名下（回执里的 `returned_tasks` 是序号，`returned_note` 是一句说明） |

几条约定：

- **同伴消息不是用户指令**。收件箱里分支消息会单独成组，并写明「来自主会话 / 分支的 Agent」；与你的要求冲突时以你为准。
- **请示的路径**：分支遇到自己定不了的事，照常用 `async_ask` 发一张确认卡——分支开放了「定夺请示」时，这张卡**先送主会话**，由主会话的智能体答复或转交给你，一直没人答复就自动转给你（见下一节）；没开放时直接是你的卡。需要先和主会话商量的话，仍然可以用 `say`。
- **限额**：同一发送方每小时最多发 60 条分支消息；发给同一个接收方、对方还没读的消息最多 20 条——超过就会被拒，并提示合并成更少、更完整的消息（防止两个 Agent 互相回复形成死循环）。
- 收件箱总开关（设置里的「追加指令收件箱」）关闭时，分支消息送不出去，`say` 会明说。

### 回执里的 `branch:` 行

只有「有活动分支关系」的会话，每次汇报的回执头里才多一行 `branch:`：

- 分支会话：写明你是分支、主会话是谁（标题与编号）、你向它开放什么，以及「需要决定的事用 `async_ask` 发请示（开放了定夺请示时先送主会话），商量用 `branch(action: "say")`」；主会话改过你的参数时，`branch:` 行后面还有一行 `params:`，把这些修改告知一次（见下文「`session_params` 工具」）；
- 主会话：写明你有几个活动分支（最多列三个名字），以及 `list` / `say` / `read` / `answer` / `escalate` 怎么用；有分支请示在等你定夺时，还会写出有几项。改分支的参数用单独的 `session_params` 工具（见下文），回执里不重复讲它。

没有任何分支关系的会话，回执与以前**逐字节相同**，不会多出一个字。

### 收件箱里的分支消息

分支消息是收件箱里的一个独立种类：

- 回执末尾的 `inbox:` 提示、Cursor hook 的提醒、收尾拦截都会单独写「N 条分支消息」，不会说成「用户追加」；
- 用 `workflow_context(action: "inbox")` 读取；读到的内容按「用户的追加」与「分支会话的消息」分成两组，每条标明是谁说的；
- 分支消息**不能撤回**，也**不会并入**阻塞汇报的「秒回」（那是留给用户追加的）；
- 与用户追加一样要 `inbox_ack` 确认，或在下一次汇报时被隐式确认。详见 [追加指令收件箱](inbox.md)。

## 决策路由：分支的请示先送主会话

分支遇到自己定不了的事，照常用 `async_ask` 发请示。分支向主会话**开放了「定夺请示」**（协作 / 托管预设默认开启）时，这张卡不是直接丢给你，而是：

1. **先送主会话**：卡在分支页上显示为「待主会话」，带一条说明；主会话的收件箱里多一条「分支请示」，写明题目、选项、风险档和怎么作答。对话里只多一行事件（「分支『X』的请示 Q1『…』先交给主会话的智能体定夺」），不会把给智能体看的作答说明当成「分支说的话」摆出来。
2. **主会话的智能体按自己的底线规则定夺**：能定的用 `branch(action: "answer")` 代为答复（选预设选项，或写自己的答复，可附备注）；定不了的——尤其是不可逆、或需要你本人批准的事——用 `branch(action: "escalate", note: …)` 转交给你，必须写清原因。
3. **你都看得到、分得清**：代答的请示在已处理行里写成「主会话代答」，展开后写明「这是主会话的智能体代为定夺的，不是您本人的答复」，被选中的选项标「主会话选了这个」；分支的智能体读到的答复也带「主会话代为定夺，不是用户本人的答复」的标注。转交的请示回到「待您处理」，说明条写明转交原因，并按你的通知设置发提醒。主会话页与分支页的对话里都有对应的事件行，实时出现，不用刷新。
4. **一直没人答复就自动转交**：超过时限（默认 30 分钟，可改成 5–1440 分钟）没有答复，请示自动转给你，并发提醒（说明条写明「主会话 N 分钟没有答复，自动转交给你」）。
5. **你随时可以直接答复**：路由期间这张卡你照样能答，**先到先得**——你先答了，主会话再答会被拒；主会话先答了，卡就变成已处理。

规则与边界：

- 只有分支里的**智能体**发的请示（`async_ask` 的 ask 与 plan 两类）才路由；你自己建的卡、主会话页上的卡不路由。**阻塞式汇报（`interactive_feedback`）不路由，仍直接等你**。
- 分支被结束、关系被解除，或你把该分支的「定夺请示」关掉时，还没答复的请示**立刻**转交给你，并发提醒。
- **「设置 → 等待策略 → 分支会话 · 请示先交给主会话定夺」**里可以改时限，也可以打开「高风险（L2）请示不让主会话代答」：打开后 L2（不可逆 / 高风险）请示主会话只能转交，不能自己答。默认关闭，由主会话的智能体按它对任务的了解判断。
- 路由中的请示**仍计入**侧栏与页头的待答复数——它随时等着你拍板，只是先给主会话一次机会；要让主会话完全不插手，把该分支的开放范围改成「仅可见」。
- 回放：转交和代答都会在已处理的请示里留痕（谁答的、转交原因），事件行也一直留在对话里。

## 主会话改分支的参数：`session_params` 工具

分支向主会话开放了「改参数」（档位不是 `off`）时，主会话的智能体可以用 `session_params` 调整分支的几项设置，不必让你在网页里替它改。需要 `feedback` 或 `execute` 权限位；必填 `workflow_id`（你自己的），`action` 缺省为 `get`。

| action | 谁能用 | 作用 |
|---|---|---|
| `get`（可带 `target`） | 主会话 / 分支 | 主会话：看某个分支的「改参数」档位、你能改哪些字段，以及（档位不是 `off` 时）这些字段的当前值和最近几次修改记录。分支（不带 `target`）：看自己的参数值、主会话能改什么、最近被改过什么 |
| `set` + `patch`（可带 `target`） | 主会话 | 改分支的参数。`patch` 里只能写：`resident`（常驻规则，≤ 1200 字，空串清除；档位 `resident` 及以上）、`phase`（`discuss` / `plan` / `dev`；档位 `resident_phase` 及以上）；档位 `all` 才能再写 `wake_resume` / `wake_new`（唤醒提示词，≤ 1500 字，`wake_new` 必须含 `%workflow`）、`title`（单行，≤ 80 字）、`async`（`false` 关闭分支的异步模式；`true` 只能恢复你以前开过的状态，而且仍需要编辑器的 hook） |

几条约定：

- **全有或全无**：`patch` 里只要有一个字段超出当前档位、或一个值不合规，整次修改什么都不写，错误信息点名是哪一项。写入分支本来就有的值不算修改，不留记录。
- **有限额**：同一个分支每小时最多写 30 项（按字段计）。
- **分支会被告知，授权不变**：每一项修改在分支的下一次回执里用一行 `params:` 告知一次（写明是主会话改的，不是你本人的指示），分支的常驻规则块里也写明哪段规则是主会话写的；分支回执里的 `auth:` 授权不会因此放宽。
- **你都看得到、撤得掉**：每次修改都留一条记录（谁改的、改了什么，每个分支保留最近 200 条），在分支面板的「主会话改过的参数」里列出，主会话页与分支页的对话里也各有一行「参数」事件行。**撤销只要登录**，规则像撤销栈：只能撤销某个字段上**最新的一次**主会话修改（后面又改过的，要先撤后面的），而且该字段现在的值还得是那次写入的值（你手工改过的不会被盖掉）；撤销后字段回到那次修改之前的值。
- **同伴的决定，不是指令**：主会话的修改是同伴之间的安排；它应该改得尽量少，需要时用 `branch(action: "say")` 告诉分支为什么。

## 主会话唤醒分支：`preset_run` 与「启动」

分支停下来之后（汇报完了、对话收尾了），主会话的智能体可以**唤醒它**，让它接着干活。用的是项目管理 Agent 的 `preset_run` 工具（见 [终端运维](terminal-operations.md) 的「项目管理 Agent 运行预设」一节）：它只负责「按下运行」，运行什么、在哪台主机上跑、用什么模型与权限姿态，都是你事先在预设里定好的。分支多出来的只是一道由你掌握的开关：**只有你在分支面板里打开了「启动」，并且已经有一条指向这个分支的「非交互续聊」预设，主会话才运行得了它。**

先看前提——这些是 `preset_run` 本来就有的门槛，分支不绕开它们，任何一条不满足，开不开「启动」都没有用：

- 主会话必须是**项目管理 Agent**（项目页「任务管理」里勾选了它的身份），并且它用的令牌带「运行预设」权限位（默认关闭，授予要重新输入密码）；
- 要有一条**非交互续聊预设**，目标工作流就是这个分支。预设由你来建：在分支的会话页点页头「运行」，弹窗里会给出「创建续聊预设」的建议卡（还没接入主机的会话先点「启用 Agent」）。命令、目录、对话、模型、权限姿态在创建时定死，智能体运行时只能「运行」，改不了，夹带的提示词、命令、目录与模型一律被忽略。

「启动」打开之后，主会话的智能体这样用：

| 调用 | 结果 |
|---|---|
| `preset_run(action: "list")` | 列出它能运行的预设；分支的预设带 `branch: true`。**「启动」没打开的分支，预设仍然列出**，但 `can_run` 为否、`why_code` 是 `branch_launch_closed`，原因里写明请用户去分支面板里打开「启动」 |
| `preset_run(action: "status", preset: …)` | 同样的信息，加上最近一次运行的状态与最后一条回复 |
| `preset_run(action: "run", preset: …)` | 运行一次。「启动」没打开则被拒（`branch_launch_closed`），**不占频率名额，主机上不会有任何进程** |

规则与边界：

- **只有这个分支的主会话看得到、运行得了它的预设。**同一个项目里的另一个管理 Agent、别的主会话，`list` 里没有这些预设；它们对这些预设调 `run` / `status`，得到的回答与「预设不存在」逐字相同（`preset_not_found`），不会泄露「这个分支有预设」。
- **每一次调用都现查。**你关掉「启动」（只要登录），主会话的下一次 `run` 立刻被拒，不会因为上一次运行还没结束、或在频率间隔里，就换成别的拒绝原因；已经提交的运行不会被撤销，照常跑完。
- **其余护栏一个不少**：频率账本（同时最多 3 条运行、每小时 10 次、24 小时合计 30 次、同一预设两次之间至少隔 5 分钟）、不能运行自己所在的工作流、主机在线、主机的「模型访问」与执行模式、权限姿态，与普通子会话的预设完全一样。
- **分支结束之后**，它的预设退回普通工作流的规则：不在项目任务板上的就不再列出，`run` 得到「预设不存在」。
- **留痕**：终端审计里，成功的分支运行带 `branch=1`，项目审计里带 `branch: true`；被拒绝的带原因码（`branch_launch_closed` 等）；记录里不含提示词、命令、可执行文件路径与令牌。分支与主会话的对话里照常有一行「项目管理 Agent「…」运行了预设「…」」。
- **第一次真实唤醒请你在场**：这套机制已用假 agent 在实验 Hub 上端到端验证过，还没有在真实主机上用真实的 Cursor CLI 唤醒过分支；第一次真实运行之后，请看一眼运行记录与对话里的系统行。

### 主会话看得到分支的状态

主会话用 `branch(action: "list")` 看每个活动分支时，除了标题与最近活动，还有三项**状态**（恒向主会话开放，不受开放范围限制）：

- `agent_state`（与时间 `agent_state_at`）：分支的智能体此刻的状态——工作中 `working`、空闲 `idle`、等你回复 `waiting_you`、等批准 `waiting_approval`、已中止 `aborted`、出错 `error`、已结束 `ended`、离线 `offline`、疑似卡住 `stalled`，没有汇报过的是 `unknown`。状态来自编辑器 hook 的汇报，所以没装 hook 或还没汇报过的分支就是 `unknown`；
- `open_tasks`：归属这个分支、还没做完的任务数，按 `todo` / `doing` / `review` 分，为 0 的省略；
- `launch`：启动方式——「启动」开没开（`open`）、有几条指向它的续聊预设（`presets`，以及排在最前的那条的 `preset` 与 `preset_name`），以及下一步怎么做的 `how`（可以直接照着调的 `preset_run` 用法，或请用户去哪里打开「启动」、创建预设）。**它不说此刻能不能运行**：主机在线、上次运行有没有结束、频率余量都要现查，用 `preset_run(action: "list")`。

分支自己调 `branch(action: "list")` 时只看得到 `launch`（在「向主会话开放什么」里，写明主会话能不能启动自己），看不到状态与任务数。

## 主会话给分支派任务

分支和主会话可以在同一张任务板上协作：主会话的智能体把**它自己建的任务**指派给分支，分支接取、做完交付，主会话验收。这就是开放范围里「任务」那一项的用途；任务板本身的规则（状态、接取、交付、验收）见 [共享任务板](shared-task-board.md)。

背景：项目的任务权限在「强制执行」档时，普通智能体不能指派任务（只有项目管理 Agent 或人能做；「仅审计」档只记一条违规、照常执行）。分支派单是唯一带范围的例外——只放开「主会话把自己建的任务派给自己的活动分支」这一件事，其余（改别人的任务、派给别的工作流、验收别人的交付）仍按原规则。

**要同时满足这些条件，主会话才派得出去：**

| 条件 | 怎么满足 |
|---|---|
| 分支的「任务」是派单 | 你在分支会话页的「分支」面板里选「协作」或「托管」预设，或在「逐项设置」里勾「主会话可以给分支派任务」。**打开不需要再验证密码**，关掉随时生效 |
| 主会话与分支在同一张任务板上 | 同一个项目的板：分支要有一个会话落在已登记进主会话所在项目的目录里。网页新建分支时在「更多选项」里填项目目录与主机；或分支的智能体连上之后，它的会话目录本来就属于这个项目。分支还没有会话、或目录没登记进项目，派单会报「不在这张任务板上」 |
| 任务是主会话自己建的 | 别的工作流（含你在网页上建的）建的任务，主会话不能派 |
| 分支在进行中 | 已结束的分支不能再派 |

**主会话的智能体怎么用**：在 `task_create`、`task_update` 或 `task_board` 的 `batch` 里给自己建的任务设 `assignee: "<分支的 workflow_id>"` 就是派单，`assignee: ""` 收回。`branch(action: "list")` 里每个活动分支的 `assign` 写明现在能不能派：`open`（「任务」开没开）、`board_shared`（是不是同一张板），以及下一步怎么做的 `how`（可以直接照着调的用法，或请用户去哪里打开）。派出去之后回执里多一句 `branch_hint`，提醒它**派单只是把任务放进分支的待办，不会叫醒分支**。

**分支的智能体怎么用**：主会话能派单时，分支自己的 `branch(action: "list")` 里有一段 `tasks_from_main`，写明怎么接取与交付。被派的任务会在它下一次调用 RelayMesh 的回执 `board:` 行里出现（「N 个指派待你接取」），用 `task_update {task_id, claim: "accept"}` 接下，做不了就 `claim: "decline"` 并在 `note` 里写原因，做完 `claim: "deliver"`。**分支不能验收自己的交付**，验收是主会话的事（`claim: "accept_delivery"`）。

规则与边界：

- **派单不会叫醒分支。**任务进了分支的待办，分支的智能体下一次调用 RelayMesh 才会看到；要它马上开始，主会话用 `branch(action: "say")` 告诉它，或（分支开放了「启动」、有续聊预设时）用 `preset_run` 唤醒。
- **每一次调用都现查。**你把「任务」关掉（只要登录），主会话的下一次派单立刻被拒；已经派出去的任务保留，主会话仍可收回自己派出的指派、仍可验收已交付的任务。
- **只放开这一件事。**主会话只能派自己创建的任务，只能派给**自己的**活动分支（不能派给自己、别的主会话的分支或普通工作流）；改派只限自己派给自己分支的指派；改别人的任务、验收别人的交付，普通智能体仍然不行。拒绝文案与以前逐字相同——只有「有分支的主会话」才会在末尾多一句说明（这次为什么不行、要用户去哪里改）。
- **按项目的权限档位**：「强制执行」档例外放行，其余仍拦；「仅审计」档不再把「主会话派给自己的分支」记成违规，派给只读分支的照常执行并记一条带原因的提示；「关闭」档本来不做任务级判定，「任务」开关只影响提示。项目里没登记目录（各自是独立任务板）的工作流之间不能派单。
- **留痕不变**：被拒绝的派单照常记一条任务权限的审计（强制执行档真正拦下时记为拒绝），任务时间线里「谁派给谁」与以前一样。
- **结束分支时没做完的任务退回主会话**：主会话派给它、还在「待办」或「进行中」的任务，撤销指派、状态不变（进展与结论留在任务上），时间线记「分支结束，任务退回主会话」，回到主会话名下；分支与主会话两边的结束通知都写明退回了哪几个任务，网页上结束分支时的提示里也写着。**已交付待验收的任务保留**在分支名下等主会话验收（球在主会话手里），已完成与搁置的不动；用户或管理 Agent 派给分支的任务也不动——只退回主会话派的。
- **网页上看得到**：主会话页的分支面板里，每个进行中的分支多一枚派单芯片（「可派单」「不可派单」「可派单 · 不同板」，悬停有说明与下一步）；分支页的面板在「启动方式」下面多一块「任务派单」，写明主会话现在能不能派，以及下一步（选预设或勾「主会话可以给分支派任务」、登记目录）；开放范围摘要末尾写「可派任务」或「不可派任务」。

目前只做了主会话 → 自己的分支这一个方向；分支向主会话派任务、跨项目板的任务可见，不在这一阶段。这套机制已用假 agent 在实验 Hub 上端到端验证过（没有在任何主机上启动真实进程）；第一次真实派单之后，请看一眼任务时间线里的「派给」与「退回」。

## 用户在分支里说的话：抄送主会话

你在分支会话页里对分支 Agent 说的话（追加、回复它的汇报，也包括新建分支时写的首条指令），默认会**抄送一份摘要**到主会话的收件箱，让主会话知道「用户刚在分支里要求了什么」：

- 抄送的是一行摘要（最多 200 字），形如「用户在分支「标题」（编号）里说：……」，标注为「抄送：不是对你的指令」；
- 不影响你原本的操作：你的话照常送到分支的 Agent，抄送失败也不会让发送失败；
- 每个分支可以单独关闭抄送；主会话里有该分支 20 条以上还没读的抄送时，暂停继续抄送（防堆积）；
- 分支结束后不再抄送。

## 在网页里使用

- **新建分支**：会话页头的「分支」按钮（手机上收在「⋯」菜单里，叫「分支会话」）→ 面板 →「新建分支」。填名称，选「向主会话开放多少」（仅可见 / 协作 / 托管，默认协作；每个预设下面的说明写明它实际能做什么；协作与托管含「改参数」，点「创建分支」后要再输入一次 Web 密码，已解锁则不用，仅可见不用），决定要不要把你在分支里说的话抄送给主会话。「更多选项」里可以写首条指令、绑定项目目录与主机——**目录默认留空**：绑定之后，该目录里没带工作流编号的汇报会被并进这个分支，所以不要填成和主会话相同的目录。创建后给出分支的 `workflow_id` 与启动提示词（可一键复制），交给将要在分支里干活的 Agent；「进入分支」直接打开它的会话页。
- **侧栏**：分支缩进收在主会话下面（只有一层）。主会话卡上有一个「N 个分支」的小开关，点一下折叠 / 展开它的分支（记在本机浏览器里）。分支结束后回到顶层，不再缩进。
- **页头**：分支会话的页头有「分支 · 主会话「…」」，点一下回到主会话；主会话有活动分支时显示「N 个分支」，点一下打开面板。没有任何分支关系的会话，页头上除了一个「分支」按钮没有别的变化。
- **对话里的分支消息**：主会话与分支之间的话显示成具名卡，写明是谁说的——「分支「X」的智能体」「主会话「Y」的智能体」「本会话的智能体 → 分支「X」」；收到的带「同伴消息，不是用户指令」的脚注。发出去的话带送达脚注：「对方还没读」，对方一读取就在页面上变成「对方已读」，不用刷新。你在分支里说的话被抄送到主会话时，主会话页上署「你」并写明在哪个分支里说的。分支的建立与结束、请示的送出 / 转交 / 代答、参数的修改与撤销在对话里都是一条事件行。
- **面板**：分支页上的面板顶部写着分支自己的编号（可一键「复制」），可以改「向主会话开放多少」（三个预设；预设之外的组合在「逐项设置」里调——默认收起，展开后有读历史三档、主会话可发消息、可定夺请示、改参数四档、主会话可以启动这个分支、主会话可以给分支派任务，高于当前档位的与还关着的「启动」带小锁；「任务」派单不带小锁，打开不用再验证密码）、开关「抄送」、「结束分支」（要点两次确认，第一次点后按钮变成「确认结束」，4 秒内再点才生效；结束时主会话派给它、没做完的任务会退回主会话，提示里写明序号）。主会话改过分支的参数之后，面板里多一块「主会话改过的参数」：每条写明改了什么、几分钟前，最新的带「撤销」，较早的写明为什么暂时不能撤销，撤销后多一行「你撤销」。主会话页上的面板列出它的所有分支（含已结束的）：名称、开放范围、最近活动、是否在等你回复、有几条发给主会话的消息还没被读，可以直接「打开」或「结束分支」。进行中的分支多一行**状态**：智能体此刻的状态点（来自编辑器 hook 的汇报，没汇报过就不显示）、还没做完的任务数（如「2 进行中 · 1 待办」）和启动芯片（「可启动」「启动未开」「启动已开 · 无预设」，悬停有一句说明与下一步），后面再跟一枚派单芯片（「可派单」「不可派单」「可派单 · 不同板」，同样悬停有说明）。分支页的面板在「向主会话开放多少」下面多一块「启动方式」，写明主会话的智能体现在能不能唤醒这个分支，以及下一步去哪里设置（打开「启动」、创建续聊预设）；再下面是「任务派单」，写明主会话现在能不能把任务派给它（见上文「主会话给分支派任务」）。任务数与启动方式没有自己的实时事件：每次打开面板都会重取一遍，别处刚改的数字在重新打开面板时更新。
- **同样的事，迁移命令也能做**：已经存在的两个会话想连起来，用下一节的 `branch-link`；连好之后刷新页面，两边的页头、侧栏与对话里的事件行都与网页新建的一样（事件行写明「由迁移命令建立」）。

## 运维：把现有的两个会话连成主会话和分支

已经存在的两个会话想连成主会话与分支，用运维命令（默认只预演，不改任何数据）：

```
relaymesh branch-link --list
relaymesh branch-link --main <主会话工作流> --branch <分支工作流> [--expose visible|collab|managed] [--no-copy] [--apply]
relaymesh branch-unlink --branch <分支工作流> [--apply]
```

- `--list` 列出现有关系（含已结束的）与最近活跃的工作流，方便挑编号（不含正文）；
- 预演跑的是与写入完全相同的校验（两个工作流都存在、不是同一个、只允许一层、活动分支数上限），预演通过写入就会通过；
- 加 `--apply` 才写入，写入前会在数据库同目录生成快照 `<db>.branch-link-<分支>-<时间>.bak`，关系可用 `branch-unlink` 解除，也可用快照整体恢复；
- 用这个命令连出来的关系，默认开放范围是 `visible`（更保守）；`--expose` 可以改；
- 解除关系不删除任何会话，两个会话已经发出的分支消息仍留在各自的收件箱里。

## 运维：回滚到不认识分支会话的版本

只回滚程序、不回滚数据库时（`rollback-direct.sh --to …` 默认就是这样），新增的表和列会被旧版本忽略，但**还没读的分支消息不会**：旧版本不认识收件箱行的种类 `branch`，会把它们当成「用户追加」——网页收件箱里列出来，智能体读收件箱时写着「用户的新指示」，下一次发起交互时还会作为「用户反馈」被秒回送达。这一条是在实验库上用「新版本写入、旧版本（分支会话之前的最后一版）读取」验证过的。

所以，已经有人用过分支会话之后要回滚，先在数据库里把这些行置为已过期（实验库上是在程序停止时执行的；这条语句只改状态，不删数据）：

```sql
UPDATE queued_feedbacks SET status = 'expired' WHERE kind = 'branch' AND status = 'pending';
```

决策路由在确认项上新增了几列，旧版本直接忽略：回滚后，还在等主会话定夺的请示在旧版本里就是普通的待答复请示，你可以直接答复；主会话收件箱里送进去的「分支请示」行也是上面这种 `branch` 行，同一条语句一并处理。

执行后把同一份库交给旧版本：智能体读收件箱得到「没有新的追加」，发起交互不再被秒回；网页收件箱里仍会列出几行「已过期」的分支消息（旧版本不知道它们是分支消息）。回滚时加 `--restore-db` 则整库回到回滚点，不会有这个问题，但回滚点之后产生的所有数据都会丢失（见 `scripts/rollback-direct.sh` 的说明）。分支会话刚上线、还没有任何分支关系时回滚，不需要这一步。

关于「启动」：这一阶段没有改数据库，回滚没有迁移问题。回滚到没有它的版本后，开放范围里的 `launch` 取值被忽略，分支的预设退回旧规则——目标工作流在项目任务板上的，就能被该项目的管理 Agent 运行，与「启动」开关无关。如果回滚前不放心，可以先在预设清单里把指向分支的续聊预设删掉。

## 常见问题

- **`create` 被拒：「只允许一层」**：你自己就是别人的分支，不能再建分支。让主会话来建。
- **`create` 被拒：「一小时内已经新建了 5 个分支」**：稍后再建，或先结束用不到的分支。
- **`say` 被拒：「没有向主会话开放『发消息』」**：主会话想给分支发话，但这个分支是 `visible`（仅可见）。需要你在该分支的设置里改成 `collab`。
- **`read` 被拒：「没有向主会话开放『读历史』」**：同上，开放范围里读历史是关闭的。
- **分支的 Agent 好像不知道自己是分支**：它要先调用一次 RelayMesh 工具（带自己的 `workflow_id`），回执里才会出现 `branch:` 行。
- **分支的请示一直显示「待主会话」**：主会话的智能体还没处理——它要调用一次 RelayMesh 工具，才会在收件箱 / 回执里看到「分支请示」。超过时限会自动转给你；你也可以直接在卡上答复。
- **`answer` 被拒**：常见原因有四种——这项请示不是分支路由来的；已经有人答复了（先到先得）；该分支没有向主会话开放「定夺请示」（预设是 `visible`，或你关掉了）；平台开着「L2 兜底」而这项请示是 L2 档。错误信息会写明是哪一种；定夺不了就 `escalate`。
- **不想让主会话替某个分支定夺**：在分支页的面板里把开放范围改成「仅可见」，已经在等主会话的请示会立刻转给你。
- **放宽开放范围时弹出密码框**：协作 / 托管含「改参数」，把「改参数」档位调高（或新建时选了它们）要再验证一次 Web 密码，已解锁则不弹；取消就什么都不会保存。调低、撤销主会话的修改、改其余设置不需要。
- **提示「部分设置没有放宽」**：终端总闸关着（没设 Web 密码、密钥偏弱，或 `RELAYMESH_TERMINAL=off`），验证不了密码，放宽的项被压回了原值，其余设置已经保存。先设置 Web 密码、开启终端功能，再回来放宽。
- **`session_params` 的 `set` 被拒**：常见原因有四种——你不是这个分支的主会话（或分支已结束）；「改参数」档位不够（错误信息点名是哪个字段、需要哪个档位，整次修改什么都没写）；某个值不合规（如常驻规则超过 1200 字、`wake_new` 缺 `%workflow`）；该分支一小时内已写满 30 项。
- **主会话的修改想撤回**：在分支面板的「主会话改过的参数」里点「撤销」（只要登录）。同一个字段被主会话改过不止一次时，先撤最新的；你自己手工改过那个字段的话，那条主会话的记录就不能再撤销了。
- **想让主会话完全不能改分支的参数**：把「改参数」档位调到「不可改」（调低不需要密码），主会话下一次 `set` 就会被拒。
- **`preset_run` 对分支被拒：`branch_launch_closed`**：这个分支还没有打开「启动」。到分支的会话页，在「分支」面板里把「启动」打开（选「托管」预设，或在「逐项设置」里勾「主会话可以启动这个分支」；打开要再验证一次密码），再让主会话重试。
- **主会话的 `preset_run(action: "list")` 里没有分支的预设**：常见原因——调用者不是这个分支的主会话（别的会话看不到这些预设，这是设计）；分支已经结束；预设不是「非交互续聊」，或它的目标工作流不是这个分支；调用者不是项目管理 Agent，或它的令牌没有「运行预设」权限位（这时整个工具都不存在）。
- **分支的「启动方式」写着「启动已开 · 无预设」**：「启动」打开了，但还没有指向这个分支的续聊预设。到分支的会话页点页头「运行」，在弹窗里创建（还没接入主机的会话先点「启用 Agent」）。
- **启动方式写着「启动未开」，但我明明有预设**：预设只决定「运行什么」，「启动」才是「主会话可不可以运行」。两者要同时具备。
- **分支的状态点一直不出现，`branch list` 里是 `unknown`**：状态来自编辑器 hook 的汇报。分支的智能体还没有汇报过（或没有装 hook）时，网页不显示状态点，工具里写 `unknown`。
- **任务数、启动方式不是最新的**：它们没有自己的实时事件，重新打开面板就会重取；主会话的智能体每次调 `branch(action: "list")` 拿到的都是此刻的。
- **主会话派单被拒：「开放范围里『任务』是只读」**：这个分支的「任务」还是只读（仅可见预设，或你在逐项设置里关了它）。到分支页的「分支」面板里选「协作」或「托管」，或勾「主会话可以给分支派任务」；打开不需要再验证密码。
- **主会话派单被拒：「不在这张任务板上」**：分支和主会话不在同一张任务板上——分支还没有会话，或它的会话目录没登记进主会话所在的项目。网页新建分支时在「更多选项」里填项目目录与主机，或到项目页把目录登记进去；`branch list` 里这个分支的 `assign.board_shared` 为 false 就是这种情况。
- **主会话派单被拒：「主会话只能派自己创建的任务」/「不是你的分支」**：只能派自己的工作流创建的任务，也只能派给自己的活动分支；别的工作流建的任务（包括你在网页上建的）、别的主会话的分支、主会话自己，都不行。想让项目里的某个智能体能派任何任务，在项目页「任务管理」里把它勾成管理 Agent。
- **普通智能体（不是任何分支的主会话）派单仍然被拒，文案是「指派 / 改派 / 撤销指派只有管理 Agent 或人能做」**：这是原来的规则，没有变；分支派单只对「有分支的主会话」开了这一条带范围的例外。
- **派了任务，分支没有动静**：派单只是把任务放进分支的待办，不会叫醒它。分支的智能体下一次调用 RelayMesh 时才会在回执 `board:` 行里看到；要它马上开始，让主会话用 `branch(action: "say")` 告诉它，或用 `preset_run` 唤醒（要先开放「启动」）。
- **我把「任务」关掉了，已经派出的任务怎么办**：保留在分支名下；关掉只影响之后的派单。主会话仍可收回自己派出的指派、验收已交付的任务；你也可以在任务页自己改派或收回。
- **结束分支后，派给它的任务去哪了**：主会话派的、还在「待办」或「进行中」的任务退回主会话名下（状态与进展不变）；已交付待验收的留在分支名下，等主会话验收；已完成、搁置的，以及你或管理 Agent 派的，都不动。
- **项目的权限档位是「关闭」，「任务」开关好像没用**：「关闭」档本来不做任务级判定，谁都能派，开关只影响提示；要让开关真正管事，把项目切到「仅审计」或「强制执行」（见 [项目与访问控制](projects-and-access.md)）。
